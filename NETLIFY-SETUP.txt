FORGE REPORT SYSTEM — NETLIFY-ONLY TEST PACKAGE
=============================================

This version uses Netlify Functions plus Netlify Blobs for persistent storage. It does NOT require Supabase, a separate database account, database credentials, or environment variables.

UPLOAD
1. Extract this ZIP. Upload the CONTENTS of the AReport folder to the root of your GitHub repository.
2. If your test repository is already connected to Netlify, keep that connection. Commit these files to that same repository and Netlify should redeploy automatically. Only create/connect a site if you have not already done so.
3. Netlify should detect netlify.toml. Build command: leave blank. Publish directory: .
4. Deploy.
5. Open the deployed site's signup page and create the first account. On a fresh storage database, the first account becomes Admin. Subsequent accounts become Department Heads.
6. Sign in as Admin and test reports, approvals/rejections, history and attachments.

STORAGE AND IMPORTANT NOTES
- Data is stored persistently using Netlify Blobs in the deployed site; it is not stored in the visitor's browser.
- No Supabase environment variables are used.
- The first-account-admin rule is intended for initial setup/testing. Create the first account yourself immediately on a new deployment before sharing the URL. Do not use this as a hardened public registration system without adding a controlled admin-bootstrap process.
- Attachments are limited to about 3.5 MB per upload and stored privately; only the submitting user and administrator can retrieve them.
- This package does not import historical records from the former SQL Server database. It starts with a fresh dataset.
- Netlify Blobs is suitable for a test deployment and modest usage. For concurrent/high-volume production use, use a transactional database and review authentication/security requirements.

ROUTES
- /api/auth/departments
- /api/auth/signup and /api/auth/login
- /api/reports (admin only)
- /api/reports/user/:userId
- /api/reports and /api/reports/:id/resubmit
- /api/reports/:id/review (admin only)
- /api/reports/:id/attachment


CHECKS AND LIMITATIONS
- The API and frontend JavaScript were syntax-checked locally, and a mocked-storage smoke test passed signup, login, report creation, admin listing/review, duplicate-account rejection, and rejection of unauthenticated API access. This does not replace a live Netlify deployment test.
- Create the first administrator account yourself immediately after deploying, before sharing the public URL. Anyone who registers first on a brand-new store can otherwise become the initial Admin.
- This is a test deployment package, not a production security review.
